# 工业标准品多平台询价与供应商比价系统

工业级多平台（1688、淘宝/天猫、京东、米思米中国）标准品询价、供应商信息聚合与型号精确匹配系统。

## 阶段0–2 本地启动与测试

```bash
# 1. 运行自动化单元测试
python -m pytest tests/

# 2. 运行阶段1 (1688单平台) 端到端验证脚本
python scripts/run_1688_test.py

# 阶段2离线闭环（1688 + 淘宝/天猫）
python scripts/run_phase2_test.py

# 阶段3离线闭环（关键词模式 + 1688 + 淘宝/天猫 + 京东）
python scripts/run_phase3_test.py

# 阶段4离线闭环（1688 + 淘宝/天猫 + 京东 + 米思米）
python scripts/run_phase4_test.py

# 3. 启动本地比价系统 Web UI 与 API 服务 (或双击 start.bat)
python run_server.py
```

阶段2已支持同时勾选 **1688** 与 **淘宝/天猫** 查询。首次使用实时
淘宝/天猫查询前，点击页面右上角“登录 淘宝/天猫”，在弹出的浏览器中
完成登录；Cookie 仅保存在本机 `cookies/taobao.json`，该目录已被 Git 忽略。

淘宝/天猫实时结果会继续读取商品详情页：以详情中的 `sellerType` 区分
**淘宝店**与**天猫店**，展示真实店铺名称；当详情规格中能唯一命中目标
型号时，页面同时展示已确认的 SKU 名称、SKU 价格、库存和发货时间。
若同一型号仍有多个不同价格的组合规格，系统保留列表价并提示人工确认，
不会把最低列表价冒充目标 SKU 价。

未登录、登录过期或平台接口异常时，系统会明确标注“离线兜底数据”，
不会把样本报价显示成实时结果。

页面提供两种查询模式：

- **工业品牌 + 完整型号**：执行品牌、完整型号、后缀和规格的严格匹配，适合标准件询价。
- **关键词搜索**：按关键词覆盖度发现相关商品，不把宽泛关键词误当成目标型号或目标 SKU。

查询完成后可在结果区按 **置信分、平台或价格** 排序，并选择升序/降序。

搜索前还可选择候选范围：

- **每个平台各取 N 条**（默认每个平台 10 条）：保障所选平台都有展示机会。
- **全平台按置信度取前 N 条**（适合前 20 排名）：全部平台合并后按置信分截取。

结果区会显示每个平台的“入选数/原始返回数”和错误原因。例如全平台 Top 20
中某平台入选 0 条时，仍可看到该平台是否查询成功以及原始返回了多少条。

阶段3已开放 **京东** 平台。首次实时查询前点击“登录 京东”，在独立
Chrome Profile 中完成登录并关闭窗口；查询时系统优先读取京东浏览器签名
搜索 API，并对前 5 个高相关商品补充详情价格、店铺与自营/第三方类型。
登录窗口可见，日常搜索和详情访问均使用无头 Chrome 在后台完成。
京东无头 Chrome 使用普通桌面 UA，避免 `HeadlessChrome` 标识触发“访问频繁”
页面；若平台仍触发风控，系统会显示原因并明确标记离线兜底数据。

阶段4已开放 **米思米中国**。系统使用无头 Playwright 通过官网安全验证，
读取品牌、产品系列、未税起价、预计发货日和详情链接。米思米搜索页返回的
是产品系列而非唯一订购型号，因此严格模式会标记为 `POSSIBLE`，并提示进入
智能选型确认完整订购型号和价格；未登录时部分品牌不公开价格，可点击
“登录 米思米”保存独立 Profile 后再次查询。

启动后在浏览器打开：
- **采购比价界面**: `http://127.0.0.1:8000`
- **Swagger API 文档**: `http://127.0.0.1:8000/docs`

## 安全与隐私说明

1. 敏感信息（`.env`, `cookies/`, `browser_profiles/`, `auth_state/`, `session/`）已在 `.gitignore` 中彻底排除，绝不上传 GitHub/Git 仓库。
2. 系统采用独立 Chrome Profile 进行人工扫码登录，风控滑块与验证码由人工处理，系统不破解、不越界自动下单。
